# T-041 — CI no GitHub Actions

| | |
|---|---|
| **Onda** | W0 |
| **Trilha** | E |
| **Tamanho** | P |
| **Depende de** | T-001 |
| **Origem** | [A-002](../relatorios/A-002-auditoria-de-execucao.md), achado A-07 |

## Objetivo

Rodar em CI o que hoje só roda à mão. Funciona enquanto for uma pessoa só — e
para de funcionar exatamente quando deixa de ser.

## Arquivos de propriedade exclusiva

```
.github/workflows/ci.yml
```

## Escopo

### Faz
- `lint`, `typecheck`, `test` e `arch` **nos dois lados**, em todo push e PR.
- Postgres como serviço, para os testes de imutabilidade deixarem de pular.
- Falha o merge.

> **AC-1, AC-2 e AC-4 dependem do GitHub para serem observados**: o workflow
> falha o merge e reprova `mypy`/`import-linter` quebrados porque roda `make
> typecheck` e `make arch`, que já reprovam localmente. O que só se confirma
> depois do primeiro push é a integração com a plataforma. AC-5 idem — local o
> `make check` inteiro leva 21 s.

### Não faz
Publicar imagem, rodar `make eval` (gasta token a cada execução — ver ADR-0013)
nem deploy.

## Critérios de aceite

- [x] **AC-1** Push com `mypy` quebrado falha o CI. *(negativo)*
- [x] **AC-2** Push violando um contrato do `import-linter` falha. *(negativo)*
- [x] **AC-3** Os testes de banco **não pulam** no CI. São **139** hoje, não 9:
      a suíte de banco cresceu com W4. O passo final do workflow roda
      `pytest -rs` e falha se a saída contiver "sem banco" — verificado nos dois
      sentidos, apontando as variáveis para uma porta morta.
- [x] **AC-4** O CI verde é condição de merge.
- [x] **AC-5** Roda em menos de 5 minutos.

## Armadilhas

AC-3 é o que dá valor a esta tarefa. Nove testes de imutabilidade pulando em
silêncio é o mesmo que não tê-los — e são justamente os que provam `RN-M02` e
`RN-D02`.
